# 产品需求

## 1. 产品目标

宣传记录助手将新闻网站、学校官网和微信公众号文章转换为适合宣传存档的 PDF，减少打印缺图、手工长截图、手工转 PDF 和手工重命名等重复工作。

产品为本地 Web 应用：用户在电脑上启动程序后，通过浏览器访问 `localhost` 使用。页面内容、生成记录和 PDF 都在本机处理，不依赖学院服务器或云端服务。

产品衡量标准不是“页面越干净越好”，而是：

- 能看出由哪家媒体发布；
- 正文与图片完整；
- 标题和日期准确；
- PDF 可追溯到原文；
- 整个过程只需要少量人工确认。

排版原则是“记录原网页”，不是“重新设计文章”。默认模式应按照浏览器屏幕中实际显示的页面高分辨率截图，保留原页面真实可见的 Logo、头部、导航、栏目、侧栏、标题、日期、作者、正文样式和图片；除广告、弹窗和遮挡层外，不主动重构页面与布局。应用自行添加的视觉内容仅限已确认的简洁存证页脚。

原网页中正常显示的导航、栏目条和侧栏允许保留，它们往往也是媒体身份与原始版面的组成部分。系统不能因为追求“干净”就机械删除；但若网页样式加载失败，使本应隐藏的菜单变成大段裸链，必须判定为渲染异常，不能把异常版面当作成品输出。

## 2. 首期用户流程

1. 用户粘贴一个网址，或每行粘贴一个网址进行批量处理。
2. 系统逐条检查、去重，并把有效网址加入本地任务队列。
3. 系统自动识别媒体、标题、发布日期、作者和来源。
4. 系统加载懒加载图片、滚动触发内容和网页字体。
5. 系统展示每条任务的 PDF 预览以及提取到的标题、日期。
6. 用户可修正标题、日期，并单独或批量切换生成模式。
7. 用户生成选中任务，查看成功、失败和待确认状态。
8. 文件按 `原标题_YYYY-MM-DD.pdf` 保存到用户选择的本地文件夹。

## 3. 生成模式

### 3.1 自动模式（默认）

自动模式默认选择原网页高保真截图引擎：

- 普通新闻网站、学校官网、微信公众号均优先记录浏览器实际显示效果；
- Canvas、GIF 和滚动动画在完成加载后截取稳定画面；
- 用户明确需要文字可搜索时，可手动切换结构化模式。

### 3.2 结构化高保真模式

作为手动备用模式，适合用户明确需要文字可选择、可搜索的普通新闻网站。该模式可能改变原网页布局，因此不作为默认存证结果。

### 3.3 截图存证模式

默认模式。适合普通新闻网站、学校官网、微信公众号和特殊动态网页。系统自动滚动并按浏览器实际显示样式分段截图，再直接分页写入 A4 PDF。该模式优先保证网页原貌，不承诺正文文字可搜索。

## 4. 页面铺满与清晰度

- PDF 默认使用 A4 纵向页面，并充分利用可打印区域；
- 默认页边距为 8 mm，允许在打印机支持时切换为 5 mm 紧凑边距；
- 内容主体按可打印宽度等比例铺开，不保留网页两侧大块无效留白；
- 禁止把整篇长文章强行缩放到一页，必须按正常阅读尺寸分页；仅当末页只有少量尾部内容时，允许整篇等比缩小不超过约 12%，以减少几乎空白的尾页；
- 标题、正文和媒体品牌不能因为保留整站宽度而缩得过小；
- 图片保持原始比例，不拉伸、不压扁，不使用会明显损伤文字的压缩；
- 除最后一页及为避免切断重要内容外，各页应尽量利用页面高度；
- 结构化模式保留矢量文字，截图模式按适合打印的高像素密度输出。

## 5. 内容保留规则

### 必须保留

- 媒体 Logo、媒体名称或有辨识度的品牌头；
- 原文标题；
- 发布时间；
- 作者和来源（网页提供时）；
- 正文、图注和正文图片；
- 原文 URL、原文二维码和采集时间；
- 能证明文章所属媒体或栏目的必要信息。
- 原网页中正常可见、版式完整的导航、栏目条和侧栏（允许保留）。

### 默认清理

- Cookie、隐私授权和登录弹窗；
- App 下载、打开客户端等悬浮提示；
- 两侧广告、浮动广告和与正文无关的横幅；
- 评论区、相关推荐和热榜；
- 分享按钮、点赞按钮及悬浮工具栏；
- 页脚备案等与报道证明无关的内容。

### 不确定时的原则

无法确定某个区域是否属于媒体身份信息时，先保留，并允许用户在预览中切换为更干净的结果。

## 6. 动态内容规则

- 懒加载图片：自动滚动并等待图片完成加载。
- GIF：默认截取有代表性的稳定帧；检测到重要动图时允许用户选择帧。
- 滚动触发动画：元素进入视口后等待动画稳定再截图。
- Canvas/SVG 动画：保存浏览器实际渲染出的静态画面。
- 视频：保留封面或代表画面，同时保留原文二维码；PDF 不承诺播放视频。
- 资源已经失效的旧文章：明确提示缺失项，不伪造或补写原内容。

## 7. 批量导入与处理

### 输入方式

- 输入框粘贴一条网址；
- 文本框每行粘贴一条网址；
- 首期不导入 CSV/XLSX；表格导入可在真实使用需要出现后追加。

### 队列行为

- 导入时规范化网址并标记重复项；
- 每条任务独立显示排队、处理中、待确认、成功或失败；
- 单条失败不应中断整个批次；
- 支持只重试失败项、取消未开始项和重新生成选中项；
- 支持批量修改生成模式和保存目录；
- 默认低并发处理，避免本机 Edge 渲染进程占满内存；
- 关闭并重新打开应用后，可恢复未完成批次和处理记录。

### 输出行为

- 成功文件直接写入选定的本地文件夹；
- 批次结束后显示成功、失败和待确认数量；
- 同名文件不得静默覆盖；
- 支持打开输出目录，以及导出本批次处理结果清单。

## 8. 文件命名

默认格式：`原标题_YYYY-MM-DD.pdf`。

处理规则：

- 替换 Windows 文件名中的非法字符；
- 去除首尾空格和连续重复空格；
- 超长标题截断，但在 PDF 内保留完整标题；
- 日期无法识别时必须由用户确认，不使用采集日期冒充发布日期；
- 同名文件由浏览器下载行为处理，系统内部归档时追加序号或短哈希。

## 9. 异常与降级

- 页面无法访问：显示具体原因，并允许重试或改用浏览器扩展。
- 需要登录或触发反爬：本地程序不读取或保存用户账号密码，转为浏览器扩展采集当前已打开页面。
- 标题或日期置信度低：要求用户在生成前确认。
- 图片未完成加载：显示缺失数量并允许继续等待或重新生成。
- 页面过长：分块渲染，禁止依赖单张超长图片拼接。

## 10. 首期范围

### 包含

- 单网址生成 PDF；
- 多行网址粘贴和批量处理；
- 本地任务队列、失败重试和批次结果汇总；
- 自动提取及人工修正标题、日期；
- 两种生成模式；
- 懒加载和常见动画处理；
- 自动文件命名；
- 原文信息与二维码；
- 本次生成状态和错误提示。

### 暂不包含

- 多用户权限和组织架构；
- 全文档案检索与统计；
- OCR 和扫描件全文搜索；
- 自动发布到公众号或新闻平台；
- 修改网页原文或用 AI 补全缺失内容。

## 11. 后续方向

- 浏览器扩展：采集已登录、反爬或仅在用户浏览器中可见的页面；
- 上传长截图并自动分页；
- 按年份、媒体、人物和活动类型归档；
- 生成记录、内容哈希和审计日志；
- OCR 搜索及宣传成果统计。

## 12. 开发前默认假设

- 首期运行在 Windows 个人电脑上；
- 启动本地程序后自动打开浏览器中的 `localhost` 页面；
- 打开系统默认浏览器，不要求安装或使用 Chrome；
- 支持 Edge 及采用 Chromium 内核的主流国产 Windows 浏览器，Chrome 可用但不是依赖；
- 所有采集和生成在本机完成，不部署线上服务器；
- 每台电脑独立保存自己的配置、记录和 PDF；
- 输入主要是公开网页；
- 中文页面为主要场景；
- 输出纸张默认 A4；
- 首期无需账号体系；
- 首期允许用户在下载前确认标题和日期。

如果需要在多台电脑之间同步记录，属于后续独立功能，不改变首期本地运行原则。
