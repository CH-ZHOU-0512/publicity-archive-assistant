# 验收与测试计划

## 1. 开发前样本集

在编写站点规则前，先收集至少 15 个经过授权的真实网址：

| 类别 | 最少数量 | 必须覆盖 |
| --- | ---: | --- |
| 学校及学院官网 | 4 | 不同站点模板、正文多图 |
| 主流媒体 | 4 | 包含极目新闻、中国新闻网等实际常用来源 |
| 微信公众号 | 4 | 普通图文、GIF、滚动动画、历史文章 |
| 特殊网页 | 3 | 懒加载、超长文章、弹窗或访问失败 |

每个样本记录：网址、期望标题、期望发布日期、期望媒体名称、必须保留区域、应清理区域、动态内容位置和人工参考截图。

真实样本及登录信息不得提交到公开仓库。需要登录的样本只记录脱敏说明，并由浏览器扩展阶段测试。

## 2. 首期功能验收

### URL 与任务

- 合法公开 URL 可以提交并显示处理进度；
- 可以每行粘贴一条网址并一次加入队列；
- 多行导入预览能准确标出有效网址、重复网址和错误网址；
- 一个批次中单条失败不影响其余任务；
- 可以只重试失败项，并能在应用重启后恢复未完成批次；
- 同名 PDF 不会被静默覆盖；
- 批次结束后成功、失败和待确认数量与实际文件一致；
- 非 HTTP(S)、本机和私网 URL 被拒绝；
- 超时、验证页和页面不存在都有明确错误；
- 同一任务失败后可以安全重试。

### 元数据

- 在正式样本集中，标题自动提取正确率不低于 90%；
- 在页面确实提供发布日期的样本中，日期正确率不低于 90%；
- 低置信度标题和日期必须提示人工确认；
- 用户修改后的标题和日期同时作用于 PDF 内容与文件名；
- 采集日期不能冒充发布日期。

### 品牌与正文

- PDF 第一页能明确识别媒体品牌或媒体名称；
- 标题、发布日期、正文及正文图片齐全；
- 不出现遮挡正文的登录弹窗和悬浮广告；
- 不因清理规则误删媒体品牌头；
- Logo、标题、日期、正文和图片应沿用原网页实际样式，不出现应用自行设计的媒体品牌头；
- PDF 与原网页的差异只能来自无关区域清理、A4 分页和存证页脚；
- PDF 末尾包含原文 URL、可扫描二维码和采集时间。

### 动态内容

- 微信图片完成懒加载后再截图；
- GIF 至少保留一个非空、可理解的代表画面；
- 滚动触发内容不会因未进入视口而缺失；
- 视频至少保留封面或代表画面；
- 动态资源加载失败时向用户报告，而不是静默生成空白区域。

### PDF 与命名

- 默认 A4，使用 8 mm 标准边距，正文主体充分铺满可打印宽度；
- 除必要边距外，不保留网页两侧大面积空白；原网页正常可见且样式完整的导航和侧栏允许保留；
- 不得把整篇长文章缩到一页，也不得为填满页面而拉伸图像；
- 非最后一页不得在没有分页保护理由时留下超过约四分之一页的空白；
- 无意外空白页、横向裁切和大面积重叠；
- 标题、主要图片和二维码不在分页处被严重切断；
- 结构化模式中的正文可选择和搜索，放大后文字边缘清晰；
- 截图模式默认按 300 DPI 输出，任何页面的有效分辨率不得低于 240 DPI；
- PDF 以 100% 比例查看和按实际大小打印时，正文、图注及图片细节清晰可辨；
- 图片保持宽高比，无拉伸、压扁和明显有损压缩；
- 文件名符合 `原标题_YYYY-MM-DD.pdf`；
- 文件名中的非法字符被安全替换。

## 3. 人工视觉验收表

每个正式样本按以下项目记录“通过 / 可接受 / 失败”：

1. 媒体品牌是否清楚；
2. 标题和日期是否准确；
3. 正文是否完整；
4. 图片是否完整、清晰、顺序正确；
5. 动态内容代表帧是否有意义；
6. 是否包含明显无关内容；
7. 分页是否自然；
8. 原文二维码是否可扫描；
9. 文件名是否正确；
10. 与浏览器中的原页面相比是否存在误导性变化。

任何“正文缺失、品牌缺失、日期错误但未提示、生成空白 PDF”均视为阻断发布的问题。

## 4. 自动化测试

### 单元测试

- URL 校验和 SSRF 地址分类；
- 标题清理；
- 日期解析与时区；
- 文件名非法字符、长度和空标题；
- 元数据提取优先级与置信度；
- 站点适配器匹配；
- 任务状态转换。

### 集成测试

- 使用本地静态夹具模拟 JSON-LD、Open Graph、懒加载、GIF、Canvas 和弹窗；
- 渲染进程生成 PDF 后检查页数、文件大小、文本和二维码；
- 检查超时、图片 404、重定向与崩溃恢复；
- 检查两个并发任务不会混用页面或输出文件；
- 导入包含有效、重复、错误和超时网址的混合批次，检查隔离、恢复与结果汇总；
- 检查每页截图像素宽度与 PDF 中的物理宽度，自动计算有效 DPI。

### 视觉回归

- 对稳定的本地夹具保存基准页图；
- 比较品牌头、标题区域、正文首图和尾部来源区；
- 真实网站变化频繁，只做人工巡检，不把像素级截图作为持续集成的硬性门槛。

## 5. 性能基线

首期目标用于发现明显退化，不作为对外承诺：

- 普通新闻页面通常在 30 秒内生成；
- 超长或动态页面通常在 60 秒内生成；
- 单任务必须有总超时；
- 渲染并发必须可配置；
- 批量处理默认低并发，任务数量增加时内存占用不应持续无界增长；
- 超长页面不得导致进程无限增长或生成尺寸为零的 PDF。

## 6. 发布门槛

- 正式样本集中没有阻断发布的问题；
- URL 安全测试通过；
- 失败页面不会产出伪成功文件；
- Edge 及至少两种实际使用的国产 Chromium 浏览器可完成提交、批量任务、预览和下载；Chrome 可兼容，但不能作为运行前提；
- 断开境外网络、未安装 Chrome 时，应用仍能依靠本机 Edge 完成普通样本处理；触发反爬或验证的样本可使用安装包自带的离线扩展完成；
- 启动器打开系统默认浏览器，不静默改用其他浏览器；
- 在目标 Windows 电脑上完成至少一次从启动应用、生成 PDF 到打印件的全流程测试；
- 断开非必要的云端服务后，除访问原文章网址外，应用仍可正常工作；
- 检查应用只监听本机回环地址，局域网中的其他电脑无法访问；
- 学院使用者对 5 份代表性 PDF 完成视觉确认。
