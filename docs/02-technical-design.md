# 技术方案

## 1. 总体架构

建议采用 TypeScript 单仓库，将本地 Web 界面、本地 API 和独立渲染进程打包在同一套应用中：

```text
用户浏览器（仅访问 127.0.0.1）
  │ 提交 URL / 查看预览 / 打开本地 PDF
  ▼
本地应用主进程
  ├─ 静态 Web 界面
  ├─ Local API
  ├─ 批量导入与校验
  └─ 本地任务、设置与恢复
  │ 创建任务 / 查询状态
  ▼
本地任务队列
  │
  ▼
隔离的 Puppeteer Core/Edge 子进程
  ├─ 站点识别与元数据提取
  ├─ 懒加载和动态内容稳定
  ├─ 结构化高保真 PDF
  └─ 分段截图 PDF
        │
        ▼
用户选择的本地文件夹
```

推荐的首期目录结构：

```text
apps/
  web/          浏览器中的本地 Web 页面
  local-api/    仅监听 127.0.0.1 的 API 与启动器
  renderer/     Puppeteer Core/Edge 渲染进程
packages/
  shared/       类型、校验、命名规则
  site-rules/   通用规则和站点适配器
docs/
fixtures/       经授权的测试网址及期望结果
```

Local API 和渲染进程应从代码层面分离。网页执行时间较长、风险较高，不能阻塞界面，也不能让被访问网页获得本地应用权限。

## 2. 建议技术栈

- Web：Vite + React + TypeScript，构建后由本地应用直接提供静态文件；
- Local API：Fastify + TypeScript，仅监听 `127.0.0.1`；
- 网页渲染：Puppeteer Core + Windows 自带 Microsoft Edge；
- 数据校验：Zod；
- 元数据：本机 SQLite；
- 任务调度：本地任务表和单独的渲染子进程，不引入 Redis 或远程队列；
- PDF 组装：Edge PDF 与支持图片分页的 PDF 库；
- 二维码：本地生成，不依赖第三方在线接口；
- 文件：用户选择的本地输出目录，生成过程使用应用专属临时目录。

正式分发包应包含应用运行时，不要求普通用户单独安装 Node.js、配置数据库、访问 Google 或在线下载浏览器。后台优先调用 Windows 现有的 Microsoft Edge；安装时离线检查 Edge 是否可用。启动器负责启动 Local API、选择空闲端口并自动打开系统默认浏览器；退出应用后停止本地进程。

启动器必须调用系统默认浏览器，不能硬编码 Chrome 或 Edge。前端构建目标采用兼容级 JavaScript，不依赖特定浏览器专属 API；文件生成和本地目录操作均由 Local API 完成。双核国产浏览器应使用其 Chromium/极速模式，不能依赖已经淘汰的 IE 内核。

不建议首期引入 OCR、AI 标题识别或复杂微服务。标题和日期优先通过结构化元数据与确定性规则提取。

## 3. 批量导入与任务队列

- 多行文本按行解析，忽略空行并报告格式错误；
- 多行文本解析为统一的导入行结构，忽略空行并报告错误；
- 导入结果先预览，显示有效、重复和错误网址数量，再确认加入队列；
- 使用规范化 URL 去重，但保留用户主动要求重复生成的能力；
- 任务和批次持久化到 SQLite，应用重启后可恢复；
- 渲染并发默认设为 1，可在性能允许时配置为 2；
- 每个任务使用独立浏览器上下文和输出临时目录；
- 批次中的单项失败只更新自身状态，不中止其余任务；
- 输出清单记录输入 URL、实际 URL、标题、日期、模式、状态、文件名和错误原因。

## 4. 元数据提取顺序

### 标题

1. JSON-LD 中 `NewsArticle.headline`；
2. Open Graph 的 `og:title`；
3. 站点适配器；
4. 页面 `<h1>`；
5. `<title>` 清理站点后缀；
6. 用户确认。

### 发布日期

1. JSON-LD 中 `datePublished`；
2. `article:published_time`；
3. `<time datetime>`；
4. 站点适配器；
5. 标题附近的日期文本；
6. 用户确认。

不得将 `dateModified`、HTTP 响应时间或采集时间静默当作发布日期。

### 媒体来源

优先使用 JSON-LD publisher、Open Graph site name、品牌头和已知站点配置；域名仅作为最后的展示回退。

每个字段都应返回 `value`、`source` 和 `confidence`，以支持预览页提示。

## 5. 页面稳定流程

1. 使用临时用户目录启动隔离的 Edge 渲染进程，并使用屏幕媒体样式而非打印媒体样式。
2. 设置桌面端视口、中文语言和固定时区。
3. 导航到页面并等待 DOM 可用。
4. 关闭已知弹窗和遮罩，不点击未知广告或外链。
5. 缓慢分屏滚动到底部，触发懒加载与动画。
6. 检查正文图片的 `complete`、自然尺寸和加载错误。
7. 等待字体就绪，并检测页面高度是否稳定。
8. 回到顶部，执行选定的 PDF 引擎。
9. 生成原文二维码、页脚和文件名。
10. 清理浏览器上下文与临时资源。

`networkidle` 不能作为唯一完成条件，因为广告、统计脚本和长连接可能永远不空闲。

## 6. A4 页面与清晰度策略

统一页面几何参数：

- 纸张：A4 纵向，必要时允许用户逐项改为横向；
- 标准边距：8 mm；紧凑边距：5 mm；
- 主体内容宽度应接近可打印宽度，不把网页左右栏和空白一起缩入 PDF；
- 默认以原网页完整可见宽度为缩放基准，保留头部、导航、栏目条和侧栏，禁止对整篇长页面执行“适合单页”；
- 图片始终保持宽高比，超过页面宽度时只做等比例缩小；
- 正文的最终打印字号不得因为页面缩放而低于可读范围。

结构化模式中的文字、线条和二维码保持矢量输出，图片尽量使用原始资源，不主动降低分辨率。

截图模式以最终落在 PDF 中的物理尺寸计算像素，而不是使用固定浏览器截图尺寸：

```text
目标像素宽度 = PDF 可打印宽度（英寸） × 目标 DPI
```

- 默认目标为 300 DPI，资源紧张时不得低于 240 DPI；
- 先裁切网页无效留白，再按目标像素宽度渲染；
- 分段高度与一页 A4 可打印区域匹配，避免二次整体缩放；
- 截图以 3 倍像素密度采集并使用高质量 JPEG（当前质量 92）写入 PDF；压缩后仍须逐页渲染验证文字和图片清晰度；
- 若末页只有少量尾部内容，允许在不低于原尺寸 88% 的范围内整篇等比缩小并居中，减少近乎空白的尾页；不得拉伸、裁切或重排网页；
- 页面切分优先选择段落间距和图片边界；最后一页除外，避免产生大面积无意义空白；
- PDF 预览提供“实际大小”检查，测试阶段必须同时检查屏幕 100% 显示和真实打印件。

## 7. 结构化高保真引擎

目标是在保持文字可搜索的同时保留媒体身份。

- 识别品牌头和文章主体；
- 克隆必要 DOM 与计算后的样式到受控打印页面；
- 优先克隆网页中实际可见的 Logo、标题、元信息和正文节点，不重新设计媒体版式；
- 如果标题或品牌只能靠应用自行重建，应标记低置信度并进入预览确认；
- 下载并内联正文图片，避免打印时跨域或懒加载丢失；
- 使用应用自己的 A4 分页样式，并把文章主体铺满可打印宽度；
- 对标题、图片、图注和段落设置合理的防断页规则；
- 在末尾追加原文 URL、二维码和采集时间；
- 原页面打印样式仅作参考，不能直接信任，因为它可能隐藏 Logo 或图片。

站点规则采用“通用识别 + 域名适配器”的组合。适配器只描述选择器和行为，不复制整套渲染代码。

## 8. 截图存证引擎

目标是保存用户实际看到的视觉结果。

- 按视口分块截图，禁止先拼接成一张无限长图片；
- 截图时保留媒体品牌头及正常显示的导航/侧栏，只隐藏弹窗、广告、悬浮按钮和因打印状态错误出现的重复菜单；
- 相邻分块保留少量重叠，组装时检测并去重；
- 优先在段落间距或图片边界分页，避免切断标题、人物面部和二维码；
- 按目标 300 DPI 计算截图宽度，保证 A4 打印后的中文清晰度；
- 裁掉网页两侧无效留白后再分页，不能将整个桌面网页等比例缩小塞入 A4；
- 对 GIF、Canvas 和滚动动画记录所选代表帧；
- 原文二维码与采集信息使用矢量文字追加，避免随截图失真。

截图 PDF 可以在后续增加不可见 OCR 文本层，但不属于首期。

## 9. 微信公众号策略

首期先由本机的 Puppeteer Core/Edge 渲染公开的 `mp.weixin.qq.com` 文章：

- 使用截图存证引擎；
- 自动滚动触发图片与动画；
- 识别封面、作者、公众号名称和发布时间；
- 检测“环境异常、需要验证、请在微信客户端打开”等失败状态；
- 失败时给出清晰提示，不输出看似成功的空白 PDF。

浏览器扩展是首期随包提供的可靠降级方案，但只在普通网址处理失败时使用。扩展按通用 Chromium Manifest V3 规范制作，随安装包离线提供，不依赖 Chrome 商店、Edge 商店或外网；可用于 Edge 及允许离线加载 Chromium 扩展的国产浏览器。扩展读取用户当前已打开的页面，以 3 倍像素密度分块截图后交给本机 Local API 组装 A4 PDF，并写入统一任务历史；本地应用不读取、不保存用户的微信账号密码和浏览器 Cookie。无法安装扩展时，主体网址转 PDF 功能仍可使用。

## 10. URL 安全

即使只在本机运行，网址转 PDF 仍存在内网探测、恶意网页执行和本地 API 被滥用的风险。首期必须包含：

- 只允许 `http` 和 `https`；
- 拒绝用户名密码形式的 URL；
- DNS 解析后拒绝本机、私网、链路本地和云元数据地址；
- 每次重定向都重新检查目标地址；
- 限制跳转次数、总处理时间、下载体积和页面高度；
- Edge 在独立子进程和临时浏览器配置中运行；
- 禁止网页下载文件、打开外部应用和访问本地文件；
- Local API 只监听 `127.0.0.1`，不得监听局域网地址；
- Local API 校验请求来源和每次启动生成的随机令牌，默认关闭跨域访问；
- 渲染进程不持有本机其他文件的访问路径或应用密钥；
- 生成接口限制并发，避免耗尽本机内存；
- 临时文件到期自动删除。

默认拒绝私网网址可能会影响校内内网页面；如后续确有需求，应采用显式域名白名单，不能整体开放私网访问。

## 11. 任务状态

建议最小状态机：

```text
queued → loading → stabilizing → extracting → rendering → completed
   └────────────── 任意阶段 ──────────────→ failed
```

错误结果至少包含：错误类别、用户可读说明、是否可重试、已提取的标题和日期。前端不直接展示内部堆栈。

## 12. 数据保留

首期默认只保存任务元数据和短期 PDF：

- URL；
- 标题、发布日期、来源及其提取依据；
- 生成模式；
- 状态、错误类别和耗时；
- PDF 临时位置、大小和过期时间；
- 采集时间与内容哈希。

批量任务额外保存批次名称、导入来源、总数和每条任务结果，便于重启恢复和导出结果清单。

如果学院要求长期归档，应在开发前明确本地保存目录、备份方式和删除规则。本地版本不自动上传或跨电脑同步。
