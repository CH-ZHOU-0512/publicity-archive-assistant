# 技术难点与项目优势

## 1. 桌面网页实际宽度超出浏览器视口

不少新闻站点使用固定宽度、`min-width`、负边距、CSS transform 或横向溢出。若直接按 1280px 视口截图，右侧正文、宽图或说明文字会被截掉。

项目会先定位最可信的正文容器，再计算容器和所有可见正文子元素的左右联合边界，加入 12px 安全留白并约束在可截图的文档表面内。普通网页和浏览器扩展使用同一原则。

## 2. 动态网页的“稳定”难以判断

网络空闲不等于页面完整。懒加载图片、内部滚动容器、Web 字体和单页应用过渡都可能在网络安静后继续变化。

项目会：

- 自动滚动页面及主要内部滚动容器；
- 激活常见懒加载属性；
- 等待字体就绪与图片解码；
- 监测文档高度连续稳定；
- 回到顶部后等待站点遮罩与过渡结束。

## 3. A4 分页既要完整，也要可读

整页缩放最容易实现，却会把长文章缩成无法阅读的小字。固定高度硬切又容易把文字切成上下两半。

项目按 A4 可打印区域换算 CSS 切片高度，收集文字行边界，尽量把切线移动到文字行之间；短尾页只在缩放不低于 88% 时合并，长图则允许像连续纸带一样自然跨页。

## 4. 微信、反爬和登录态无法由单一路径覆盖

主程序使用独立 Edge 环境，隐私更清晰，但不会继承用户日常浏览器登录态。遇到验证页时，继续自动重试既不可靠，也可能触发更严格限制。

项目采用双路径：公开页面走隔离 Edge；验证或登录态页面由用户先在浏览器中正常打开，再用离线扩展采集当前可见内容。扩展不导出 Cookie 或密码。

## 5. 元数据需要“可靠”，不是“猜出来”

标题和日期会影响文件名与归档检索。项目按结构化数据、开放图协议、站点字段和页面标题逐级判断，并过滤明显不合理的时间。无法可靠识别时暂停任务让用户确认，绝不把采集时间冒充发布日期。

## 6. 本地工具仍要防御不可信网页

用户输入的 URL 和页面子资源都来自不可信网络。项目限制协议、拒绝凭据 URL，并对域名解析结果、重定向和子资源进行检查，阻止访问回环、私网、链路本地及云元数据地址。API 仅监听本机并要求会话校验。
